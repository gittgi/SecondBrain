##  HTTP 3

- [HTTP 2](HTTP%202.md) 역시 여전히 TCP를 사용하기 때문에 초기 연결에 대한 [RTT](../네트워크/네트워크.md) 로 인해 지연시간에서 길어진다는 단점
- HTTP 3에서는 이를 QUIC (Quick UDP Internet Connections) 계층 위에서 UDP 기반으로 작동하는 것으로 초기연결설정시 지연시간 감소
	- HTTP2의 장점인 멀티플렉싱 등 유지

- HTTP2의 경우 클라이언트와 서버간의 연결을 맺어 세션을 만드는데 필요한 핸드셰이크, 암호화통신 구축을 위한 TLS 핸드셰이크가 각각 필요 (3 - RTT 필요)
- HTTP3는 TLS로 암호화통신을 구축할 때의 단 한번의 핸드셰이크를 활용해 클라이언트와 서버간의 연결, 암호화 통신 모두 다 구축
	- 이를 통해 1 - RTT만에 모든 연결 성립

- 또한 열악한 네트워크 환경에서도 낮은 패킷 손실률을 보이는 순방향 오류 수정 메커니즘 (FEC, Forward Error Correction)을 통해 수신측에서 에러를 검출 및 수정할 수 있음
