##  HTTP 2

- 2011년 [HTTP 1.1](HTTP%201.0과%201.1의%20차이.md)의 한계를 극복하기 위해 구글에서 SPDY 프로토콜 개발
- 2015년, SPDY를 기반으로 하는 HTTP 2 프로토콜 개발

## 특징

### 바이너리 포맷 계층
- 애플리케이션 계층과 전송 계층 사이에 바이너리 포맷 계층 추가
- HTTP 1.1이 일반 텍스트 메세지를 전송하고, 줄바꿈으로 데이터를 나눈것과 달리
- 2.0은 바이너리 데이터로 전송하며, 더 작은 메세지가 프레임으로 캡슐화 되어 전송됨

### 멀티플렉싱
- 1.1에서는 병렬요청을 하려면 다중 TCP 연결을 해야함
- 2.0에서는 리소스르 작은 프레임으로 나눈 뒤, 스트림으로 프레임을 전달
	- 각각의 프레임은 스트림 ID, 해당 청크의 크기를 나타내는 프레임이 추가
	- 작게 나눠진 후에 비동기적으로 받게 되더라도 원래 순서대로 재조립 가능
- 따라서 단일 TCP 연결의 여러 스트림에서 여러 HTTP 요청과 응답을 비동기적으로 보낼 수 있고, [HOL](HTTP%201.0과%201.1의%20차이.md) 문제 해결

### 서버푸시
- 서버가 요청된 html파일과 함께 다른 리소스를 클라이언트에 푸시 (요청 없이 전송) 가능
- 대표적으로 html에 포함된 css 파일이 있다면, 별도의 요청 없이 css도 같이 푸시 ㄱ가능

### 헤더압축
- 1.1 에 존재하는 무거운 헤더를 압축
	- 중복되는 헤더는 제외하고, 공통 필드로 헤더를 재구성
	- 중복되지 않은 헤더값은 허프만 인코딩[^1] 압축하여 전송

### 우선순위
- 서버에서 원하는 순서대로 우선순위를 정해 리소스를 전달 가능


[^1]: 허프만 인코딩 : 문자열을 문자 단위로 쪼개, 빈도수가 높은 정보는 적은 비트 수로 표현, 빈도가 낮은 정보는 비트 수를 많이 사용하여 표현하는 것으로 전체 데이터 표현에 필요한 비트 수 절약
